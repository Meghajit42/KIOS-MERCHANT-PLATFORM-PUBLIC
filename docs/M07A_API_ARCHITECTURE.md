# M07A private API v1

Six read-only capabilities at `/api/v1/{merchant,outlet,catalogue,availability,configuration,operational-status}`. Disabled by default (`KIOS_PRIVATE_API_ENABLED=0`). Private gate, demo environment, platform/lifecycle infrastructure and all public/financial/printing restrictions must remain in force. No standalone public API host, registration, order/payment/delivery write endpoints or token issuer is provided.

Authentication: normal private-demo HTTP gate plus an existing native merchant staff browser session. Sign in through the existing merchant login and its CSRF form. HttpOnly/Secure/SameSite=Strict session properties, eight-hour expiry and revocation remain native. Basic gate authentication alone is not merchant authority. Bearer tokens are rejected rather than trusted. No cross-origin access is granted; never embed demo credentials in a mobile app. Future customer/delivery clients need a separately authorized public identity/token and consent design before integration. Do not expose these private APIs to them yet.

Every request selects merchant and outlet UUIDs and resolves current native membership/RBAC. Information/catalogue/availability require ReadOrders; configuration/operational summary require ManageOutlet. Plan/module menu entitlement is enforced, with native POS drain-read checks for operational summary. Final current identity/membership/entitlements are locked and revalidated before response. Platform administrators do not impersonate merchant sessions. Data fields are allowlisted and exclude contacts, addresses, credentials, audit payloads and financial records.

All methods other than GET/HEAD return405, including writes without CSRF. These APIs have no business-write operation, so CSRF cannot mutate business state. Read replay produces no business mutation, separate server request IDs and append-only access audit events. Idempotency-Key is rejected400 until a separately qualified mutation contract exists. A principal-global fixed window admits60 authenticated requests/minute; anonymous peers20. Peer identifiers are HMAC-hashed, not stored raw. Current rows serialize concurrent final-slot requests. Retry-After60 is conservative. Window storage is bounded per encountered principal/peer; operational retention for old anonymous buckets is a documented future maintenance need, not an unbounded public endpoint.

Migration035 adds API limit rows and immutable API access events. Audit failure rolls back counters and yields503 with no successful payload. No request headers, cookies, passwords, bearer values or raw query strings are logged. Successful reads contain an API version, request ID, data, error and pagination. Errors: INVALID_REQUEST400, AUTHENTICATION_REQUIRED401, ACCESS_DENIED403, NOT_FOUND404, METHOD_NOT_ALLOWED405, RATE_LIMITED429, UNAVAILABLE503. Disabled API returns404. HEAD has the same access decision and no body. No stack traces or database diagnostics are returned.

Pagination: page1..10000, per_page1..100, default20. Optional q is at most80 UTF-8 plain-text characters and filters displayed names. Scope and query values must be scalar strings; unknown fields rejected. Data is deterministically ordered by native record order; pages are independent reads and not promised a cross-request snapshot. Current native catalogue eligibility/pricing services remain authoritative; a catalogue response is not checkout authorization. Availability describes only the selected outlet; operational counts contain no customer/payment details. UTC epochs and existing database defaults retained.

Local qualification uses the existing hardened Sandbox, trusted PHP8.3/MariaDB/Node/browser tools, synthetic seed and default-off feature sequencing. Do not execute application tests or provision databases on the unisolated host. Run tests/run.php, prior M04–M06 suites, tests/tools/m07a-api.php, m07a-browser.js and full synthetic dump/restore/migration replay inside the approved guest. No production credentials or network mapping. Deployment needs a qualified private rewrite from api paths to the existing guarded merchant wrapper; never route around the private gate. GitHub Actions and automatic deployment remain disabled.

Example (placeholders only): GET /api/v1/merchant?merchant=MERCHANT_UUID&outlet=OUTLET_UUID. A browser already signed in normally can use same-origin fetch with credentials same-origin. Response: {"api_version":"v1","request_id":"SERVER_GENERATED_ID","data":[{"merchant_id":"MERCHANT_UUID","name":"Synthetic restaurant"}],"error":null,"pagination":{"page":1,"per_page":20,"total":1}}. Do not put sessions/tokens in URLs. Keep future v2 changes additive/versioned; clients should ignore unknown response fields and handle explicit error codes. No SDK credentials or hosted settings belong in source.

Read requests accept no body; a nonempty declared request body is rejected. The controller returns a versioned error envelope on bootstrap failure and on requests exceeding its 64 KiB bound (413 REQUEST_TOO_LARGE). HEAD always omits its body. The outer private-site authentication gate may return its own HTTP challenge before the application runs.
